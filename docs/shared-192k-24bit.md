# 192kHz/24bit FLACの共有出力

2026-11-03、Windows 11 / Music Center for PC 2.7.4 x86 / DirectSound共有出力で検証。192kHz/24bit/2chのWAVから可逆変換し、音声データの一致を確認したFLAC 1ファイルを使用した。Music Centerのファイルプロパティーで保存先・FLAC形式・192kHz・24bit・2chを照合し、同名のWAVと区別した。

## 変更

通常版`flac24_override`のFLAC適用条件とON判定に192000Hzを追加した。48/96kHzと同じSony FLAC sourceへの16→24bit指定変更を使い、サンプルレートは変更しない。既知のモジュール版・呼び出し元、DirectSound選択、24bit・ステレオのガードと失敗時の16bitフォールバックを維持した。初回と次曲準備の既存呼び出し元もそのまま対象とする。

WAV用のDSEE設定補正・接続変更を有効にする変更ではない。WAVは`flac24_wav192_experiment`に限る。DSDも変更対象に含めない。

## 実測

| 観測点 | 結果 |
| --- | --- |
| FLAC sourceへの指定 | `SET_24 requested=16 applied=24`、成功 |
| DirectSound実再生バッファー | 192000Hz / 整数PCM 24bit / 2ch / block align 6 |
| DirectSound内部WASAPI | 共有192000Hz / float32 / 2ch |
| 状態表示 | `HR-BR ON` |
| レンダラー入力の冒頭20秒 | 23,040,000バイトが変換元WAVと全バイト一致、不一致0 |
| 下位8bitが非ゼロのサンプル数 | 7,649,432、16bitのゼロ埋めではない |

Windowsのオーディオデバイス設定は192kHz。上記一致はレンダラー入力での結果で、Windowsミキサー通過後やDAC実出力までのビット完全一致を示すものではない。

## 操作と曲末

- 時間表示の進行、一時停止からの再開、曲末付近へのシークを確認。
- 295.284秒へシーク後、Seamless入力に残り29.01609375秒分の33,426,540バイトが到達。元音源の終端324.30009375秒までのデータ量に一致した。
- レンダラー入力にも最終サンプルが到達し、端数のパディングを含めてEOSを処理した後にDirectSoundが停止した。数秒分の最終データが未到達のまま停止する現象は、この試験では認められなかった。
- 1曲リピート後も192kHz/24bit・ONを維持。
- リピートをオフに戻して同じFLACを「次に再生」へ追加し、曲末からの自動移行後も192kHz/24bit・ONを維持。
- 44.1kHz/16bit WAVへ手動で切り替えると44.1kHz/16bit・OFFとなり、192kHz FLACへ戻すと再び192kHz/24bit・ONへ復帰した。

同一ファイルの再生試験であり、異なる192kHz曲間、複数パーサーの先読み、長時間動作、厳密なギャップレスは未検証。実際に曲間でDirectSoundの停止・再構築を観測しており、無停止連続出力の証明ではない。外部録音による曲末の検証も行っていない。

## 再現

通常ランチャーの同梱DLLがこの対応を含む。Music Centerを完全終了してDLLを更新し、ランチャーから起動する。DirectSoundを選択し、EQはオフで検証する。音源のレートを共有出力まで維持するには、Windows側の設定と機器もそのレートに対応している必要がある。

診断時は通常DLLに`probe.dll`と`end_probe_pcm192.dll`を併用し、出力形式、レンダラー入力PCM、EOSを測定した。これらの診断DLLや取得PCMは配布ZIPには含めない。私的な曲名・保存パス・生ログ・音源データもリポジトリへ含めない。
