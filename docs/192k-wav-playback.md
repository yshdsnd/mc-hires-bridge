# 192kHz/24bit WAVの実再生検証

2026-11-03、Windows 11 / Music Center for PC 2.7.4 x86、DirectSound共有出力。192kHz/24bit/2ch WAV 1ファイルでの結果。通常配布版にはまだ組み込んでいない。

## 結果

- DirectSound実再生バッファー：192000Hz / 24bit / 2ch / 整数PCM / block align 6。
- DirectSound内部のWASAPI：共有192000Hz / float32 / 2ch。
- レンダラー入力から取得した20秒、23,040,000バイトは元WAVの冒頭20秒とバイト単位で一致。不一致0。
- 24bitの下位8bitが非ゼロのサンプルは7,649,432個。16bitのゼロ埋めではない。
- 時間表示の進行、一時停止・再開、曲末付近へのシーク、曲末から対象外のDSD曲への移行を確認。
- 1曲リピートでも修正後は192kHz/24bitとHR-BR ONを維持した。
- 44.1kHz/16bit WAVへの手動切り替えでは変更を見送り、実バッファー44.1kHz/16bit、HR-BR OFFとなった。

照合箇所はDirectSoundレンダラーの入力。Windowsミキサー通過後やDAC実出力のビット完全一致を示すものではない。ギャップレスの厳密な保証、別ファイル間の192kHz連続再生、長時間安定性は未検証。

## 本体で判明した処理

Music Center本体は、このWAVをWindows標準WAVパーサーで開いていた。Sony純正パーサーだけを想定した最初の試作は適用されなかった。

OpcWavEx.dllの確認済み呼び出しから、DSEE独自slot 3へ、入力192kHz/24bit・出力44.1kHz/16bitを指定するところを捕捉した。呼び出し元の戻り先RVAは0x33E47、OpcWavExのPE timestampは0x63EB12E7。DSEE設定のmodeは初回1で、後から別の呼び出しで同じ形式を再設定する動作もあった。

入力の精度は元から保持されており、DSEEに指示された低い出力形式が後段へ伝わっていた。

## 試験版の処理

既知の版・呼び出し元と192kHz/24bit/2chの条件で、DSEEの準備用設定を192kHz/24bitへ補正する。その後、停止状態の初回Pause/Run前にDSEEとEQを迂回する。これによりSeamlessへ最初から高い形式が渡る。

初回の経路：

```
標準WAVパーサー → Seamless → DirectSound
                 全接続192kHz/24bit
```

繰り返し時には、Seamlessを使わない経路が構築された。この形は標準WAVパーサーに限って次の接続へ変更する。

```
標準WAVパーサー → DirectSound
          192kHz/24bit
```

Sony純正WAVパーサーからSeamlessを外す処理は追加していない。フィルターオブジェクトを削除・置換せず、接続変更に失敗した場合は保存した形式と位置を戻す。補正済みDSEEが接続されたままの場合は再生を進めない。

## 曲末

192kHz曲末付近へシークした実測では、残り28.4400938秒、32,762,988バイトがSeamless入力とレンダラー入力の両方へ到達していた。その後にDirectSoundが停止して次曲へ移行した。前のFLAC修正で問題になった「最終サンプルが届く前の停止」は、この測定では認められなかった。レンダラーから実デバイスまでの全バッファーを外部録音した試験ではない。

Seamlessの通知3841は維持し、標準完了イベントの偽装や固定秒数待機は追加していない。

## 制限と現在の状態

試験DLLはflac24_wav192_experiment。既存の48/96kHz FLAC用処理は残すが、今回192kHz FLACの実ファイルは検証していない。DSDにも変更を適用しない。試したDSDへの移行時は44.1kHz/16bit出力・HR-BR OFFだった。

通常のランチャー、常用DLL、配布ZIPは更新していない。実アプリ検証用のDLLは検証終了時にアプリ再起動で解除する。私的な音源情報、保存パス、取得PCM、生ログはリポジトリへ含めない。

詳細な適用条件と独立検査方法は[wav192-experiment.md](wav192-experiment.md)を参照。
