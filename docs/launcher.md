# MC HiRes Bridge ランチャー

## 普段の起動

`MC HiRes Bridge.exe`をダブルクリックしてください。Music Center for PCが起動し、ブリッジを自動ロードします。確認画面や黒いコンソールは出ません。ヘッダーの`HR-BR RDY`が準備完了の目印です。対応音源の再生時には`HR-BR ON`になります。

EXEと`flac24_override.dll`を同じフォルダーに置いてください。フォルダーごと好きな場所へ移動でき、EXEのショートカットからも起動できます。通常の権限で使用してください。Music Center本体や音源は変更しません。

Music Centerがすでに起動している場合は、そのプロセスへロードします。すでにブリッジが準備完了なら重ねてロードしません。ランチャー自体は常駐せず終了します。Music Centerの完全終了でブリッジも解除されるため、以後はこのランチャーから起動してください。

ロード前から再生中だった曲へは遡って適用しません。次の曲、または曲を選び直したときから適用します。旧版のブリッジや別のフックが入ったプロセスへ新しい版を重ねる用途ではありません。DLLを更新した場合もMusic Centerを完全終了してから起動してください。

## エラーが出た場合

成功時のダイアログはありません。起動・ロード・初期化に失敗した場合だけ、理由とエラー番号を表示します。

- DLLが見つからない：EXEとDLLを同じフォルダーへ戻してください。
- 旧ブリッジの初期化完了を確認できない：Music Centerを完全終了してからランチャーを実行してください。
- 起動先が見つからない：現時点ではProgram Files (x86)以下のSony/Music Centerという標準インストール先を対象としています。

## 対応範囲

Windows 11 / Music Center for PC 2.7.4 x86。DirectSound共有出力の48・96・192kHz・24bit・ステレオFLACがブリッジの対象です。192kHzは1ファイルでの[実再生検証](shared-192k-24bit.md)に基づきます。44.1kHz/16bitなど対象外の音源ではOFFです。WAVは別の試験ターゲットで、通常配布には含めません。RDYやONはDAC出力のビット単位一致を保証するものではありません。Windows側の共有出力設定と機器も音源のサンプルレートに対応させてください。

## ソースからビルド

Visual StudioのC++開発環境とCMakeを使用します。

```powershell
cmake -S . -B build-Win32 -A Win32
cmake --build build-Win32 --config Release --target mc_hires_bridge
cmake --install build-Win32 --config Release --prefix "package/MC HiRes Bridge"
```

ランチャーはWin32 GUIアプリで、外部のinject.exeやPowerShellを使用しません。対象の実行ファイルのフルパスとメインウィンドウを確認し、同じアーキテクチャのプロセスへ同梱DLLをロードします。DLLからの名前付きイベントでフック初期化の成功／失敗を受け取ります。ロード済みモジュールの確認と起動用mutexで重複実行を避けます。ランチャーは音声の取得・保存を行いません。

独自ソースは同梱のBSD 2-Clause License。DLL内で使用するMinHookのライセンスは`licenses/MinHook.txt`にあります。

## 検証記録（2026-11-01、Issue #9）

- Win32 GUIランチャーと同梱DLLをビルドし、installでEXE・DLL・説明書・ライセンスだけのフォルダーを生成。
- Music Center未起動から起動し、DLL初期化完了、ランチャー終了コード0、HR-BR RDY表示を確認。手動のDLLロード操作や成功ダイアログは不要だった。
- Music Centerだけを通常起動した状態から、同じプロセスへ自動ロード。プロセスID・メインウィンドウを維持し、READYと終了コード0を確認。
- 再実行および2つのランチャーの連続実行は終了コード0。対象のメインプロセスとロードされたブリッジはいずれも1つだった。
- DLL不足のテストではエラーウィンドウの生成を確認。新アプリのComputer Use操作承認がタイムアウトしたため、文面の目視とOK操作は未確認。テスト用プロセスのみ終了した。

起動完了の判定はLoadLibraryの戻り値だけではなく、DLL自身からの初期化完了イベントを使用する。プロセスID再利用で以前のログが残っていても初期化できるよう、DLLログはSTART行を区切りとして追記する。初期化に失敗した場合は失敗イベントで通知する。読込中のタイムアウト時は、対象がまだ参照している可能性のあるDLLパスのメモリーを解放しない。

非標準インストール先、別バージョン、管理者権限で実行された対象、読み込み中にアプリを終了する場合などは実測していない。既存の観測DLLや旧版ブリッジを安全に解除する機能は追加していない。

## アイコン

斜め上から見た石造りの二連アーチ橋に、紫と水色の八分音符が浮かぶ画像をEXEへ埋め込んでいる。元画像はassets/launcher.png、Windows用はassets/launcher.ico。ICOを同梱しているため、通常のビルドで画像変換ソフトは不要。元画像を変更した場合はWindowsのPowerShellで .\tools\make-icon.ps1 を実行してからビルドする。16・24・32・48・64・128・256pxを収録し、透明度を保持する。

Win32ビルド後にEXEからアイコンを取り出し、採用した画像が埋め込まれていることを確認した。

以前の横向きの橋と箱のアイコンは、[素材一覧](../assets/README.md)に記載のファイルに保存している。
